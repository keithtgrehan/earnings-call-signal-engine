# Netflix Multimodal Review Risk Audit

This audit records the remaining reviewer-interpretation risks that were worth hardening in the final Netflix reference-case pass.

| File / section | Exact reviewer-risk issue | Why it is risky | Preferred safer interpretation | Exact fix to apply |
| --- | --- | --- | --- | --- |
| `data/demo_cases/netflix_q1_2022/demo/multimodal/netflix_model_comparison.json` and derived panel JSON | `consensus_label` could imply clean agreement even when comparable labels were tied or mixed. | Reviewers can overread a mixed sidecar row as having a settled sidecar view. | When sidecar labels are mixed, show only a leading label if one label clearly wins; otherwise say the leading label is tied. | Replace `consensus_label` with `leading_sidecar_label`, add `leading_sidecar_label_is_tied` and `tied_leading_sidecar_labels`, and rename `label_counts` to `sidecar_label_counts`. |
| `data/demo_cases/netflix_q1_2022/demo/multimodal/netflix_model_comparison.json`, `netflix_disagreement_hotspots.json`, and panel payloads | `deterministic_alignment`, `alignment`, and `support_signal_bucket` sound more scientific or validating than intended. | Those names can be read as proof, validation, or correctness scoring instead of reviewer triage. | These rows should read as bounded review categories and expected-direction checks only. | Rename to `expected_direction_check` and `review_bucket`, and use less claimy bucket values such as `consistent_directional_read`, `softened_directional_read`, and `directional_conflict`. |
| `data/demo_cases/netflix_q1_2022/demo/multimodal/netflix_audio_support.json` summary and notes | `audio_confidence_support` and “confidence inference” wording can be mistaken for truth confidence rather than signal usability. | Reviewers may overread measured pause/filler cues as certainty or intent judgments. | Audio should be described as measured cue availability only. | Rename `audio_confidence_support` to `audio_signal_usability` in the persisted bundle and keep notes narrowly on pause, filler, qualification, and pacing. |
| `data/demo_cases/netflix_q1_2022/demo/multimodal/netflix_visual_support.json` summary and moment rows | `visual_confidence_support`, `support_direction`, `support_note`, `confidence_note`, `strongest_visual_evidence`, and `most_confident_visual_segments` still sound stronger than heuristic context warrants. | The heuristic fallback layer can still look like corroboration or a stronger evidentiary signal than it is. | Visual output should read as bounded context, quality gating, and reviewer usability only. | Rename those persisted fields to `visual_signal_usability`, `context_role`, `context_note`, `quality_note`, `most_reviewable_visual_segments`, and `most_usable_visual_segments`, while keeping heuristic-fallback wording explicit. |
| `docs/netflix_multimodal_evidence_panel.md` opening section | The panel started directly with showcase rows and caveats, but not with blunt interpretation rules. | A reviewer skimming fast could jump into moment notes before seeing the intended reading order. | The panel should tell reviewers how to read it before they inspect any moments. | Add a short `How To Read This Pack` section that says transcript first, same-direction sidecars are not proof, disagreements are priorities not winners, and audio/visual are bounded context only. |
| `docs/netflix_multimodal_panel_summary.md` comparison section | Pairwise model stats and the old heading could read as a quality claim rather than a bounded comparison snapshot. | Reviewers may mistake model-to-model agreement for evidence that a sidecar is correct. | Treat these numbers as narrow comparison stats only. | Add interpretation rules near the top, rename the section to `Supporting-Layer Comparison Snapshot`, and describe the numbers as comparable-label same-label rates. |
| `docs/netflix_multimodal_pr_description.md` summary and guardrails | The prior PR text was accurate but did not make the “reference-quality bounded demo case, not proof of generalization” point unavoidable. | Reviewers could still assume the branch was making a broader multimodal claim than intended. | The PR should read as a final hardening pass on a single Netflix reference case. | Tighten the PR text so it explicitly states transcript-first canonical status, Netflix-only scope, heuristic visual fallback, supporting-only layers, no predictive/statistical claims, and no generalization claim. |
| `data/demo_cases/netflix_q1_2022/demo/multimodal/README.md` boundary and read order | The README was good on scope, but it still lacked a blunt “what not to infer” layer. | Reviewers or later UI work can reuse files without carrying forward the intended interpretation rules. | The README should travel with the pack as the fast start + fast caveat document. | Add a short interpretation-rules section that says transcript first, same-direction is not proof, disagreement is not a winner, and audio/visual remain bounded context only. |
| `src/earnings_call_sentiment/netflix_multimodal_panel.py` reviewer-note wording | Phrases like “cleaner support examples” and repeated “corroboration” cautions still kept the stronger term in circulation. | Even cautionary use of stronger terms can anchor reviewers on the wrong mental model. | Use comparison/context language instead of validation/corroboration language. | Rewrite reviewer notes and visual caveat text to say “cleaner comparison examples,” “bounded observational context,” and “does not change the transcript-backed read.” |
